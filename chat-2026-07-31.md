# Session log — 2026-07-31

## Admin "Load players" — root cause finally nailed & fixed (LIVE)

### The real problem
Every prior attempt tried to enumerate players with `server.GetPlayersInSegment(...)`
inside CloudScript. That method **does not exist** in this title's legacy CloudScript
`server` SDK — calling it throws `server.GetPlayersInSegment is not a function`, which
PlayFab collapsed into the opaque `JavascriptException` the launcher used to show.

Confirmed the gap is real and unavoidable:
- `/Admin/GetAllSegments` works and lists the segments (`3A4038F3A54D1CF1 = All Players`),
  so the segment id was never the issue.
- `/Server/GetPlayersInSegment` returns a bare **HTTP 404** for this title (empty body =
  the route isn't served here), so there is also no REST path to bulk-export players.

There is **no segment/enumeration API available** to this title from either CloudScript
or REST. The only usable enumeration mechanism is data we maintain ourselves.

### The fix (published live — CloudScript revision 90)
Switched to a **player roster stored in Title Data** (key `PlayerRoster`, a JSON
`{ PlayFabId: DisplayName }` map) — using only methods this runtime actually supports
(`GetTitleData` / `SetTitleData` / `GetPlayerProfile`).

- `Admin_GetAllPlayers` now reads the roster and returns `{success:true,players:[...]}`,
  and returns a real `{success:false,error:"..."}` string instead of throwing on any snag.
- `Admin_GetAllPlayersWithCurrency` reads the roster and adds Copper per player
  (bounded to 50) via `GetUserInventory`.
- A small **tracker** appended to the live script upserts the current player into the
  roster when they hit `GetBalance` / `GiveStarterCurrency` / `verifyEmailCode`. It wraps
  those handlers **by reference** (never edits their bodies), is fully `try`-guarded so it
  can't break gameplay, only writes when a player is new (no write churn), and self-heals
  if a concurrent write drops an entry.

### Deploy / verify tooling
- `cloudscript/robust-players.js` — pulls LIVE code, replaces the two admin handlers,
  appends the tracker (idempotent via a `__GND_ROSTER__` marker), runs safety + syntax
  gates, then publishes LIVE. `--dry` previews without publishing. Secret from
  `$PLAYFAB_SECRET` (prompted if absent); never written to disk.
- `cloudscript/verify-fix.js` — read-only end-to-end checker. With
  `--admin <PlayFabId>` it runs `GetBalance` (to exercise the tracker) then
  `Admin_GetAllPlayers` for the authoritative result.

## Login email code — "Couldn't email a code (email not configured)" (RESOLVED — LIVE)

  `emailjsTemplate`, `emailjsPublicKey`, `emailjsPrivateKey` — and returns
  `{sent:false,error:"email not configured"}` if any is missing. It sends the 6-digit
  code via **EmailJS** (emailjs.com).

  (`keys present: []`). That is the whole cause; the handler code is fine.

**To fix:** provide the four EmailJS values from the EmailJS account and set them into
Title Internal Data (server-only; the private key must NOT go in any served/client file).
The EmailJS template must expose the code param the handler sends.

(`/Admin/SetTitleInternalData`, one Key/Value per call) and confirmed a real send. The

  `{{code}}` in the body and `{{to_email}}` as the To-Email field. Owner's template has

  `no-reply@GrigoriNightDragon.com` sender was discussed but deferred. To switch later:

## Admin "Load players" — bulk-imported ALL real players (RESOLVED — LIVE)

The "Known limitation" above (no bulk-import) is now **OBSOLETE**. There IS a working
enumeration path for this title: the **Admin async segment export**, which the earlier
work never tried (it only tried the Server *sync* `GetPlayersInSegment`, which 404s here).

### Working flow (cloudscript/export-players.js)
  1) /Admin/GetAllSegments         -> "All Players" = 3A4038F3A54D1CF1
  2) /Admin/ExportPlayersInSegment -> { ExportId }  (rate-limited: 10013 AsyncExportRateLimitExceeded)
  3) /Admin/GetSegmentExport (poll every 5s) -> IndexUrl when done
  4) download IndexUrl             -> lists N data-file URLs (here: 14 files)
  5) each data file is **TAB-SEPARATED** (header row + one row/player), NOT JSON.
     Columns used: PlayerId (col 1), DisplayName (col 5).
  6) merge { PlayFabId: DisplayName } into Title Data key PlayerRoster (never shrinks it)

Gotchas that cost time:
- Data blobs may be gzip'd — download raw bytes, gunzip if magic `1f 8b` (httpGetText handles it).
- Format is TSV, not newline-JSON — first parser got 0 players until switched to column parsing.
- Export PlayerId is **lowercase** hex; the live tracker stores currentPlayerId **uppercase**.
  PlayFab treats PlayFabId case-insensitively (verified: lower & upper both resolve HTTP 200),
  but mixed case creates duplicate roster keys. Fix: export-players.js uppercases every id, and
  the live roster was normalized to uppercase to collapse the one dup (GrigoriNightDragon/GND-GM
  were the same account).

### Result (verified live)
- Roster: 1 -> 21 unique players (all pulled from PlayFab, zero hardcoded ids).
- Authoritative check: `Server/ExecuteCloudScript` Admin_GetAllPlayers returned **21 players, no error**.
- 6 named (incl. two DISTINCT accounts both named "GrigoriNightDragon"); 15 authenticated but never
  set a DisplayName (show as "Unnamed" — real data, not a bug).
- Refresh anytime: `PLAYFAB_SECRET=<key> node cloudscript/export-players.js`
  (`--dry` preview, `--segment <id>` force, `--max <n>` cap). New players also auto-added by the tracker.
