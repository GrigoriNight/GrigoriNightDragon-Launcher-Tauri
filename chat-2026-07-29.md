## Assistant
Two features. For email verification I used a **custom 6-digit code** (PlayFab's
native link flow can't carry a code). For password reset, PlayFab's Client API has
**no set-password call**, so fully in-app password entry is impossible — the
achievable path is a **"Forgot password?"** link that triggers
`SendAccountRecoveryEmail` (PlayFab emails a reset link). Confirmed both with the
owner.

### Backend — CloudScript (`cloudscript/main.clean.js`)
Added two handlers, keeping the code **server-side** (the client never receives it):

- `sendEmailCode({email})` — reads EmailJS credentials from **Title Internal Data**
  (server-only), generates a 6-digit code, stores `{code,email,expires:+15min}` in
  the caller's **User Internal Data** (client can't read it), and sends the email via
  the classic CloudScript `http.request` to the EmailJS REST API. Returns only
  `{sent:true}` — never the code.
- `verifyEmailCode({code})` — compares against the stored record; on a valid,
  unexpired match it sets **User ReadOnly Data** `emailVerified="true"`
  (client-readable), clears the stored code, and returns `{verified:true}`.

_(tools: Bash, Edit)_

### Client — email verify UI (`src/Launcher.html`)
- After a successful registration, the modal no longer closes; it switches to a

- The logged-in account panel shows **Email verified ✓** or **not verified — Verify

### Client — Forgot password (`src/Launcher.html`)

## User

## Assistant
Created a drop-in **UE5.8 C++ plugin** at `ue5.8/GNDPlayFab/` (copy `GNDPlayFab` into a
project's `Plugins/`). It's a `UGameInstanceSubsystem` — callable from C++ and Blueprint —
that mirrors the launcher's PlayFab REST integration:

- **`Login(EmailOrUsername, Password)`** — picks `/Client/LoginWithEmailAddress` vs
  `/Client/LoginWithPlayFab` by whether the id contains `@`; stores the session ticket +
  PlayFabId; fires `OnLogin`.
- **`Logout()`** — discards the local ticket (PlayFab sessions are stateless); fires
  `OnLogout`.
- **`GetStore()`** — `GetStoreItems` → `GetCatalogItems`, merged by `ItemId` into
  `FGNDStoreItem[]` (id, name, description, class, currency prices); fires `OnStoreLoaded`.

Uses UE's HTTP + Json modules; config (`TitleId 17CBF3`, `StoreId 01`,
`CatalogVersion Items_Items`) matches the launcher and is overridable in `DefaultGame.ini`.
No secrets — client auth is the session ticket via `X-Authorization` only. Files:
`.uplugin`, `Build.cs`, module cpp, `GNDPlayFabTypes.h`, `GNDPlayFabSubsystem.h/.cpp`.

An independent verification subagent returned **PASS** (static review — no UE toolchain on
the Termux host), confirmed by a spot-check re-running the marker/secret scans.
Compilation must still be done on the Windows desktop in UE5.8.
