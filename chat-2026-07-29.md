### Rust — crash-log capture (`src-tauri/src/lib.rs`)
Rewrote `launch_game` to pipe the child process `stdout`/`stderr` through reader
threads into `app_local_data_dir/last-run.log`, with a header (timestamp, exe path)
and the process **exit code** (non-zero ⇒ likely crash). Added a `read_crash_log`
command that returns the tail (~16 KB) of that log, and registered it in
`generate_handler!`. (Desktop code is `#[cfg(not(target_os="android"))]`, so it must
be `cargo build`-validated on the Windows desktop — the Termux/Android host can't
compile it.)

### Bridge (`src/bridge.js`)

### Bug modal + JS (`src/Launcher.html`)

  `readonly` + muted.
- `openBugReport()` is now async: it auto-fills the locked fields and, when the

- `buildReport()` adds a `Target: Game|Launcher` line and a `---- crash log ----`
  section when a log was captured.
- `sendBugEmail()` gates: a Game report while signed out shows "Please sign in to
  report a game bug, or switch to Launcher." and stops; Launcher reports send

## Assistant
Two features. For email verification I used a **custom 6-digit code** (PlayFab's
native link flow can't carry a code). For password reset, PlayFab's Client API has
**no set-password call**, so fully in-app password entry is impossible — the
achievable path is a **"Forgot password?"** link that triggers
`SendAccountRecoveryEmail` (PlayFab emails a reset link). Confirmed both with the
owner.

### Backend — CloudScript (`cloudscript/main.clean.js`)
Added two handlers, keeping the code **server-side** (the client never receives it):

- `sendEmailCode({email})` — reads EmailJS credentials from **Title Internal Data**
  (server-only), generates a 6-digit code, stores `{code,email,expires:+15min}` in
  the caller's **User Internal Data** (client can't read it), and sends the email via
  the classic CloudScript `http.request` to the EmailJS REST API. Returns only
  `{sent:true}` — never the code.
- `verifyEmailCode({code})` — compares against the stored record; on a valid,
  unexpired match it sets **User ReadOnly Data** `emailVerified="true"`
  (client-readable), clears the stored code, and returns `{verified:true}`.

_(tools: Bash, Edit)_

### Client — email verify UI (`src/Launcher.html`)
- After a successful registration, the modal no longer closes; it switches to a
  **verify sub-view** ("We emailed a 6-digit code to …") with Verify / Resend / Skip,
  and calls `sendEmailCode` immediately.
- The logged-in account panel shows **Email verified ✓** or **not verified — Verify
  now**, reading `emailVerified` from ReadOnly data on login.

### Client — Forgot password (`src/Launcher.html`)
Refactored the recovery call out of `resetPassword()` into a shared
`sendRecovery(email)`; added a "Forgot password?" link under the Log-in button and
`forgotPasswordLogin()`, which reads the email from the login field and reports the
result inline.

_(tools: Edit, Read)_
